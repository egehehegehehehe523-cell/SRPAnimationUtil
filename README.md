# SRP Animation Util (0.1.18 development prototype)

Minecraft 1.12.2 Forge 14.23.5.2860, Tabula 7.1.0, iChunUtil 7.2.2, SRP 1.10.9. Install alongside these mods, do not replace them. Automatic import uses a single Tabula mixin discovered via the MixinConfigs manifest (Cleanroom/CleanMix or MixinBooter 11+). Client-only. No SRP code or assets are bundled.

## Workflow
Open Tabula directly from the main menu or from a world, choose its normal Import Minecraft Model dialog, select a registered SRP entity model and confirm. The addon uses Tabula's ModelInfo (entity class, model class and texture) to discover and sample native animations, create a named rig and append editable clips in the same project. No mob needs to be spawned or targeted, and no game world needs to be loaded. All automatic samples use a detached client preview World (no chunks, no disk saves, no server), based on Tabula’s own import-world fallback. The log reports the selected model and import result. Animated SRP imports always create a dedicated new local project instead of merging geometry into an unrelated model. Saved projects reopen unchanged. Non-SRP imports and remote/hosted sessions retain standard Tabula behavior. If sampling fails, the normal importer remains available.

Optional manual recording for movements not represented by automatic sampling:
1. Look directly at a parasite. F7 starts recording actual rendered native poses; F7 again stops. Keep the mob in view and let it perform the desired behavior. A recording is limited to 60 s and 120,000 joint samples.
2. Alternatively F8 discovers numeric status branches from model bytecode using ASM source analysis and samples each on fresh model and unspawned preview entity instances. Both still and moving inputs are sampled; identical tracks are deduplicated. No live entity state is changed. Models without compatible constructors or shared status fields need live capture.
3. Open the regular Tabula editor. F9 imports the pending captures into a new project, or appends clips to the selected compatible project without replacing existing clips. Open the regular Animate window and edit/add/split components, scrub, play and save the .tbl project. Bindings can be changed in Minecraft Controls.
4. Repeat to append other native movements. Pending captures are held in memory until imported; save projects before exiting.

## Automatic support
No entity class table. SRP entities are detected by their registry namespace; the live renderer supplies the actual model. Every ModelRenderer in the inherited box list and model fields is traversed, including unnamed/empty joints and multiple boxes. Stable names and a hierarchy/geometry fingerprint prevent cross-rig imports. Captures use native Tabula additive components with initial offsets followed by incremental position and rotation changes. Geometry/texture stay local.

Live captures sample once per observed game tick; if the entity is culled or temporarily invisible, the missing interval is interpolated. Baked samples use isolated entity instances and are two seconds at 20 ticks/second and are not guaranteed to be seamless loops. Rotations are degrees and translations use model pixels; native offsets are folded into the pivot at 1/16 model scale. Animation names are editable in Tabula. The warning in the 7.1.0 Animate window is suppressed while the addon is active (no disk config write); paused preview time is synchronized with the timeline before rendering.

## Source audit
The provided SRParasites-1.10.9.jar contains 158 top-level client/model/entity classes; 148 directly extend ModelSRP. ModelSRP exposes procedural swingX/Y/Z and moveY helpers; examples override the standard ModelBase rotation method. Native animations are not a standalone asset library. This automatically discovers direct getParasiteStatus comparisons and switches, not every possible native branch. Numeric state names are retained rather than guessing attack names. Derived expressions, entity-specific timers, custom rendering and native gameplay duration are not inferred. Renderer layers, custom OpenGL transforms, visibility, alternative submodels and unusual UV/inflate behavior are not yet represented. Shared/cyclic model parts are rejected rather than corrupted.

Tabula 7.1.0 source: https://github.com/iChun/Tabula/tree/b53c4ed70a28c56562e8b8e0361df2ab0aa02fed
iChunUtil 7.2.2 source: https://github.com/iChun/iChunUtil/tree/5cd18d371f70b798ceb3fabc6da4d72715322a88
Both already contain Animation, AnimationComponent and GUI editing code. This extension uses their public APIs; no upstream source copied.

## Build / limitations
Run Gradle 8.8 with JDK 17 and JDK 8 toolchain, or use GitHub Actions. Exact CurseMaven dependencies pinned. This is the first implementation, not a verified 1.7 feature-parity restoration. Existing Tabula timeline bugs still require live investigation. ## Bone animation workspace (Animate in Tabula's top toolbar)
For a local imported SRP rig, open Animate. This is an alternative editor inside the existing Tabula GUI, not a new screen session or project format. The left panel lists ordinary Tabula clips; the right panel lists joints only. Select a joint in the collapsible outliner or click its visible cube in the viewport. Cuboid-face depth picking selects the frontmost owning joint; only its bone transform is edited. Blue depth-tested edges outline the selected joint's own geometry (descendants if it is an empty pivot). The skeleton sticks are removed. Picking uses cuboid bounds, not per-pixel texture opacity. Right drag orbits; wheel zooms; drag the selected joint's coloured transform handles to edit the corresponding channel. G/R/S selects move/rotate/scale; X/Y/Z selects axis. Numeric fields and +/- controls are also available. Set key commits the preview pose at the current tick to native AnimationComponent tracks. The central lower timeline shows seconds, position/rotation/scale rows and diamond markers for component boundaries, with scrubbing, playback, wheel zoom and Shift+wheel pan. The viewport includes a checker background, fixed rest-pose floor grid and orientation axes. New creates a regular Tabula clip; Rename and +20t edit the clip; Apply returns to the same project, then use Tabula's normal Save/Save As. Cancel discards this editor's working copy. The native imported animation data is unchanged unless deliberately edited, including its original sampled poses and loop setting.

Bone mode recognizes both old indexed imported joint names and the explicit srpau:bone metadata on new imports. Geometry is clickable for selection of its owner but never edited directly here. Its preview evaluates Tabula's own AnimationComponent interpolation, with hierarchical local transforms including scale. It uses the same model/texture, but a separate orthographic viewport rather than Blockbench's actual renderer. The UI is inspired by Blockbench but uses Tabula's native interpolation and tick granularity; it is not an exact copy of Blockbench's full feature set. Imported samples still represent fixed native input sequences rather than a complete symbolic translation of SRP Java animation code. No artificial loop-closing or motion smoothing is applied. In-game runtime playback remains separate future work.

## Player attachment preview
Select a parasite bone (click its cube or use the outliner), then click Attach player in the right sidebar. A vanilla Steve reference model attaches at its torso centre to the selected bone's evaluated local transform, including all ancestor rotations, translations and scale. It follows the bone while scrubbing, playing, or editing the animation, even if another bone is selected. Attach to selection rebinds it and resets the offsets. Adjust attachment opens local XYZ position (model pixels) and rotation (degrees), a reference size multiplier, reset and copy controls. Hide/show and detach are independent of animation editing. The dummy is not pickable, and never adds geometry, bones, animation channels, or data to the .tbl project. Copy puts the bone identifier and offsets on the clipboard for future runtime integration. Preview state is session-only. The player is 32 model pixels tall by default; renderer-specific SRP scaling is not inferred, so use the size control if needed to match actual in-game proportions. This is a preview, not a gameplay grab implementation.

The Animate toolbar button now uses Tabula's native textured button type with a blue-only transparent icon, a tooltip and a separate hitbox. The local toolbar reflows on resize to reserve the animation slot; narrow layouts compact the right text controls and, if necessary, the icon row.

## Transform gizmos
G shows red/green/blue parent-space translation arrows, R shows Euler-axis rotation rings at the true joint pivot, and S shows local scale handles. Click and drag a handle to edit its axis; the selected/hovered handle turns gold. The gizmo is drawn over the model, while the cube outline and player attachment preview remain active. Camera changes are blocked during a drag. Auto key is on by default and commits one native Tabula edit when a changed drag is released; disable it and use Set key for manual commits. Escape during dragging restores the starting preview. Rotation uses the projected ring ellipse with a tangent fallback for edge-on views, not an arbitrary horizontal-drag multiplier. No change to the .tbl format or importer. This version implements individual axis handles, not plane or free-rotation handles.

## Adventurer rig and gizmo update
Gizmos have fixed 32.5 GUI-pixel radius regardless of zoom, larger arrowheads and scale squares, depth-tested occlusion, and full toolbar names. The Adventurer (ModelInfPlayer) is upgraded automatically on import or opening Animate: four halfway splits using rear elbow and front knee hinges like Mo' Bends. Original joint IDs, sampled tracks, and texture pixels are preserved; UV strips are repacked into additional atlas space using standard Tabula box UVs. Cut faces use the original cap texture. No Mo' Bends dependency is needed for this editor operation. Existing projects are upgraded on a working copy; Apply & back commits. Requires an original texture at the model's declared dimensions and unmodified 4x12x4 limb geometry. The editor works independently of Mo' Bends. Gameplay integration is optional and requires the Alpha.3 geometry API.

## Gameplay stationary foot planting (experimental)
When Mo' Bends Alpha.3 is installed, the Adventurer draws four split limbs via its native BoxFactory and BoxSplitter. The substitutions occur only inside ModelInfPlayer's root render call; no native animation code, original model fields, AI, hitbox or armour renderer is replaced. Idle/turning planting uses an independent world-space anchor and two-segment IK solver inspired by the core:step_turn driver (not the driver itself): plant at current native foot positions, step one foot at a time when its horizontal drift exceeds 2.1 model pixels, and lift/replant over five ticks. No terrain raycasts. Only grounded stationary status-0 mobs at normal size qualify; attacks, running, riding, swimming and nonstandard scale revert immediately to native motion. No leg planting/split substitutions when leggings or boots are equipped; arms stay native under chest armour. No edited TBL gameplay playback yet. The integration is client-only, uses a weak per-entity state cache and restores the native model after every draw. It is source/bytecode reviewed against SRP 1.10.9 but needs in-game testing, especially yaw and renderer scale.

0.1.9 fixes Adventurer limb splitting when iChunUtil truncates the 64x55 texture UV of the right leg to -1. Corrects native UV origins within one pixel, logs exact rejection reasons, and makes newly inserted hinges empty pivots. Existing native animation tracks and the original rig signature are preserved.

0.1.10 retains Alpha.3's edge hinges at the halfway point of each limb. Existing split projects receive a one-time seam atlas upgrade without changing joint IDs, pivots or animation keys. Open elbow cut surfaces and knee cap texture sampling now follow player.json/BoxSplitter; the editor uses a tiny uniform inflation approximation for Tabula compatibility, gameplay uses the native X/Z inflation. Gizmos use 48.75 GUI-pixel radius and filled 3.5/5.5-pixel strokes rather than driver-dependent OpenGL line widths. Native captured animations still have zero added-joint rotation until keyed; world-space gameplay foot planting is not automatically baked into the editor.

## Keyframe retiming and history
Click a timeline diamond to select its channel and tick. Drag it horizontally to move it, or use Shift+Left/Right to nudge one game tick at a time (20 ticks/s). A key can meet, but not cross, its immediate channel neighbour. Moving a tick-1 key to tick 0 collapses the incoming ramp into an instantaneous native offset; an outgoing ramp is retimed to preserve its endpoint. Offset-only components display only their actual start key. Other bone/channel components are left unchanged; mixed components are split only when necessary. At a shared destination their additive effects combine, rather than overwriting the neighbouring pose. Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes. History covers committed pose keys (including auto-key drags), retiming, clip creation, rename, loop changes and length extensions; last 64 edits within the open Animate session. It does not include camera, selection, temporary attachment or geometry migration changes and is not saved to TBL. Apply & back and save normally. No importer or gameplay changes.

## Adventurer authored idle test
The user-provided ModelInfPlayer.tbl (SHA-256 recorded in the asset) contained 40-tick Native idle and walk samples. The bundled adventurer_idle_edits.json is a lossless extraction of the 15 authored Key/Return components (rotation offsets/changes and position offsets); native sampled tracks are intentionally not replayed. The root position offsets and two opposing leg pitch edits sum to zero in the source. Four bend tracks and two upper-leg yaw offsets are applied to the existing runtime split limbs, not the native fields. The authored elbow curves ping-pong over 80 ticks (their start/end angles differ) while all SRP procedural motion runs natively. Four-tick smooth idle entry/exit; special states, attacks and airborne entities immediately bypass the overlay. Foot planting initializes after idle entry and targets the authored knee stance. The original renderer and armour fallback stay in place. Requires Mo' Bends Alpha.3; this is an experimental client-only test, not a general TBL player. No changes to ExtinctionCore. The original uploaded TBL is not embedded; only extracted edits are bundled.

## Full idle replacement and elbow seams (0.1.13)
The active idle resource is now adventurer_idle_full.json, compiled from all 94 bone poses of the supplied TBL (41 integer-tick samples, seven deduplicated curves, five decimal places). Every position and Euler rotation is evaluated absolutely, rather than adding only authored edits to SRP's native pose. This is not weighted skinning or a change to TBL. Existing split projects migrate their atlas once. Gameplay and editor visual verification are required.
